## Coverage

- **Android, Flutter target:** 51,429 of 52,938 `android.jar` methods generated (97.1%).
- **iOS, Flutter target:** 11,092 of 11,937 Foundation and UIKit methods generated (92.9%).
- **App size:** the Flutter Android release APK is the same size whether it binds 24 types or the whole SDK, because unused code is tree-shaken. React Native doesn't tree-shake, so you generate only what you use.

## How it works

1. **SDK discovery.** `native_api_android` reads `android.jar`; `native_api_ios` extracts Objective-C headers with libclang.
2. **Canonical IR.** `native_api_ir` holds a platform-neutral JSON model of every class, method and type.
3. **Generators.** `native_api_flutter_android` emits Dart over `package:jni`; `native_api_flutter_ios` over `package:objective_c`; the React Native targets emit TypeScript over a JSI/C++ runtime.
4. **Reason codes.** Anything not generated is reported with the reason, so coverage is auditable instead of silent.

## Known limits

- Flutter on iOS can't implement protocols or pass some escaping blocks yet.
- Kotlin `Flow` is an opaque object on React Native.
- Kotlin default arguments aren't applied through JNI.

Status: beta (`0.1.0-beta.1`), tested end to end on emulators and simulators, not yet on physical devices.
